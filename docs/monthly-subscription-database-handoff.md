## Delivered contract

[shared/schema.ts](../shared/schema.ts) adds six tables and select types;
existing workspace/storefront IDs, entitlement columns and manual writer remain
unchanged. UUID keys are supplied by the application, requiring no UUID extension
or new sequences. Binding is `{workspaceId,provider,merchantAccount,mode}` where
workspace ID references the existing `provider_subscriptions.id`.

- `billing_accounts`: unique workspace/account scope and processor customer
  identity; nullable customer while remote creation remains uncertain.
- `billing_subscriptions`: remote identity, one nonterminal contract per
  workspace/mode, calendar-month EUR offer metadata, period/evidence dates,
  generation/revision and reconciliation lease. No arbitrary annual offer.
- `billing_invoices`: separately unique invoice identity, exact numeric(18,0)
  monetary evidence (TypeScript decimal strings), paid/unpaid/reversed normalized
  status, period, refund/dispute references and reconciliation time.
- `billing_operations`: request fingerprint/idempotency and checkout slot.
  **`resolved_at IS NULL` retains the checkout slot even when `state=completed`
  means the hosted URL was created.** Resolve only after confirmed remote expiry/
  terminal absence or transactionally establishing the protected contract slot.
  Neither URL creation, timeout nor local lease expiry releases the slot.
- `billing_events`: durable event identity/fingerprint, safe object references,
  processing/lease/retry state. Unmapped events may retain null account/workspace;
  those fields must be null together. Processed events require a valid binding.
- `manual_pro_grants`: independent source intervals, issuer/revocation provenance
  and idempotent source reference. Legacy administrator attribution retains the
  original unbounded string rather than truncating or inventing a user FK.

Composite FKs enforce account/workspace/provider/merchant/mode agreement, including
invoice-to-contract and mapped-event-to-operation links. No financial/grant FK
cascades deletion. State/mode, interval bounds, fingerprint, amount and lease-pair
checks are declared in both Drizzle and generated SQL. The database does not infer
paid coverage, commercial policy or authorization from those rows.
